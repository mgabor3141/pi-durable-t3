# Capabilities

Every call T3's web app makes, and what this host answers. ✅ works · 🔜 next (refused with "… yet") ·
🕐 later · ❌ never (refused on purpose). A refused call returns a message the UI shows. A refused stream
ends with that message rather than hanging open.

| Area | Calls | | Notes |
|---|---|:-:|---|
| Connection & config | `server.probe`, `server.getConfig`, `server.getSettings`, `server.refreshProviders`, `server.reportClientActivity`, `subscribeServerConfig`, pairing, tickets | ✅ | `getSettings` answers T3's settings document; the config stream pushes `settingsUpdated` |
| Connections (pairing & devices) | `/api/auth/pairing-token`, `/api/auth/pairing-links`, `/api/auth/pairing-links/revoke`, `/api/auth/clients`, `/api/auth/clients/revoke`, `/api/auth/clients/revoke-others`, `subscribeAuthAccess` | ✅ | T3's Settings → Connections, replicated: mint and revoke pairing links, list devices, revoke one or all others. Revoking a device ends its live socket. Shown only when the host is the app's primary environment (the web app served by the host); T3's desktop app shows its own machine there |
| Web app (`webApp`, optional) | static serving, `/pair`, `POST /api/auth/browser-session`, cookie-authed REST + `/ws` | ✅ | T3's static serving (SPA fallback, ETag revalidation, traversal guard) and its browser sessions: a pairing code exchanged for an `HttpOnly`, `SameSite=Lax` cookie, honored only on same-origin requests |
| Tailscale Serve (`tailscaleServe`, optional) | `server.getConfig`'s `directEndpoints`, tailnet `Host`, `tailscale serve` at start/stop | ✅ | the host reads `tailscale serve status` first and arms `tailscale serve --https=<port> --bg http://127.0.0.1:<bound port>` only when that port is free or already points at its own port (a port mapped elsewhere is refused with a warning and never released — deliberately safer than T3, which arms unconditionally); it releases its own mapping on a graceful stop. `directEndpoints` is the tailnet Serve URL only — listed once it answers as this server (no LAN-address advertisement). No `Host` check, like T3: a request Serve forwards to loopback carrying the MagicDNS `Host` reaches the same routes and the same credential check. A Serve failure is a warning, never a dead host (T3's rule for this path). Off by default: no `tailscale` command runs |
| Shell & thread reads | `orchestration.subscribeShell`, `orchestration.subscribeThread`, `orchestration.getThreadProjection`, `orchestration.launchThread` | ✅ | projects ride the shell snapshot |
| Threads | `orchestration.dispatchCommand`: `thread.create`, `thread.delete`, `message.dispatch`, `run.interrupt`, `thread.model-selection.set` | ✅ | create, prompt, steer, queue, interrupt, delete |
| Undo | `checkpoint.rollback` | ✅ | forks before the reverted message; history is never rewritten |
| Model & thinking | `modelSelection` on create/launch/prompt, `thread.model-selection.set` | ✅ | passed through. Thinking is T3's `thinking` option, offered only for models that reason. A run's model is read from the message pi recorded |
| Crash resume | `message.dispatch` and the resumed run | ✅ | see the clip in the README. A client that is open across a restart re-subscribes (`subscribeThread` with `afterSequence`) and is answered with a full snapshot whose user turn carries the client's own message id, so a message it was holding stays one copy. A page open across a restart can reload onto the browser's error page (T3's one-shot chunk-reload guard); Reload restores it |
| Sidebar bookkeeping | `thread.visit`, `thread.mark-unread`, `thread.settle`, `thread.unsettle`, `thread.auto-settle`, `thread.auto-settle.set`, `thread.pin`, `thread.unpin`, `thread.pin.reorder`, `thread.active.reorder`, `notification.delivery.accept` | ✅ | acknowledged; T3 keeps these client-side |
| Projects | `projects.mutate` (`project.create`/`update`/`delete`), `projects.ensureScratch`, `/api/projects/mutate` | ✅ | ids honored, the same folder can't be added twice, removing a project removes its threads but not its files. `ensureScratch` is T3's "No project": a project at the integrator's `scratchDir`, each thread in a folder of its own |
| Thread launch in a worktree | `orchestration.launchThread` with `workspaceStrategy` `worktree`/`existing_worktree` | ❌ | no git worktrees on this host: `root` is honored, every strategy runs at the project root (a Scratch thread's own folder is the bridge's claim, not a worktree) |
| Settings | `server.updateSettings` | ✅ | T3's merge and validation, replicated, plus the model picker's per-key preference ops (`setModelFavorites`, `setModelsHidden`, `setProviderModelOrder`, `favorites`, `providerModelPreferences`, `migrateModelPreferences` only while unset) — star, hide and reorder a model, and they persist and broadcast. Not replicated: the other per-key special cases (background activity, project overrides, source control, usage maps, model-selection options), secret redaction, provider history |
| Folder picker | `filesystem.browse` | ✅ | directories only, for Add project |
| Thread fork | `thread.fork`, `thread.merge_back` | 🔜 | undo already forks |
| Thread rename | `thread.metadata.update` | 🔜 | |
| Archive, snooze | `thread.archive`, `thread.unarchive`, `thread.snooze`, `thread.unsnooze`, archived-shell snapshot/subscribe | 🔜 | |
| Queued messages | `queued-*`, `queue.resume` | 🔜 | pi-durable has the queue; editing it from the UI is missing |
| Attachments (images) | `assets.persistChatAttachments`, `assets.createUrl`, `GET /api/assets/*` | ✅ | images only. Stored under `stateDir/attachments/`, served by signed URL, sent to the model only if its catalog accepts images |
| Attachment uploads | `attachments.createUploadUrl`, `attachments.delete`, `POST /api/attachments/upload/*` | 🕐 | not advertised, so the client sends images inline instead. Non-image files need this path and are not supported |
| Thread search | `orchestration.searchThreads` | ✅ | T3's matching, ranking and snippets over every thread's messages. No index: each query reads every thread |
| File search | `projects.searchEntries`, `projects.searchContents` | ❌ | reads files, refused with the rest of file access |
| Usage | `server.getUsageSummary`, `server.refreshUsageRates` | ✅ | T3's bucketing and de-duplication over the usage pi records per turn. Cost is pi's reported figure (no rate table, so no cache savings); counts each thread's current history |
| Scheduled tasks | `scheduledTasks.*` | 🕐 | |
| Host diagnostics | `server.getHostResources`, `server.getProcessDiagnostics`, `server.getProcessResourceHistory`, `server.getTraceDiagnostics`, `server.getResourceTelemetryHistory`, `server.retryResourceTelemetry`, `subscribeResourceTelemetry`, `server.signalProcess`, `server.getBackgroundPolicy`, `server.reportHostPowerState`, `subscribeBackgroundPolicy`, `server.getDatabaseStorage` | 🕐 | `server.getDatabaseStorage` (new in 0.1) is not advertised, so T3 never asks |
| Workflow scripts, turn items | `orchestration.getWorkflowScript`, `orchestration.getTurnItem` | 🕐 | |
| File access | `projects.readFile`, `projects.writeFile`, `projects.listEntries`, `projects.createNew` | ❌ | the agent edits files itself (`projects.createNew` makes a Git repository, which this host has none of) |
| Git, PRs, diffs, worktrees | `git.*`, `pullRequests.*`, `vcs.*`, `sourceControl.*`, `review.*`, `projectClone.*`, `worktreeSetup.*`, `subscribeVcsStatus`, `subscribeWorktreeSetup`, `subscribeProjectClones`, `orchestration.getTurnDiff`, `orchestration.getFullThreadDiff`, `thread.pull-request*`, `server.discoverSourceControl` | ❌ | the agent uses `git` itself |
| File restore on undo | `checkpoint.rollback` with `restoreFiles: true` | ❌ | files belong to the agent |
| Terminal | `terminal.*`, `subscribeTerminalEvents`, `subscribeTerminalMetadata`, `orchestration.subscribeCommandOutput` | ❌ | tools run in the Harness. Command output streaming is not advertised, so T3 never asks |
| Editor, previews, browser | `shell.openInEditor`, `preview.*`, `mcpApps.*`, `subscribePreviewEvents`, `subscribeDiscoveredLocalServers` | ❌ | |
| Devices, relay, cloud | `device.*`, `cloud.*`, `subscribeDeviceState` | ❌ | another machine is another Harness |
| Providers | `provider.*`, `provider.switch`, `server.updateProvider`, `server.*AcpRegistry*` | ❌ | one provider, pi. T3's other providers show as Disabled |
| Approvals, plan mode | `runtime-request.respond`, `thread.user-input.dismiss`, `thread.runtime-mode.set` (other than `full-access`), `thread.interaction-mode.set` (plan) | ❌ | pi runs tools without approvals |
| Orchestrator-internal | `delegated_task.*`, `prepared-run.*`, `provider-session.detach`, `thread.created.record`, `thread.title.regeneration.complete` | ❌ | no such objects in pi-durable |
| Server lifecycle | `subscribeServerLifecycle` | ✅ | `welcome` and `ready`, then silence: the app waits for them, and this host never self-updates |
| Self-update, keybindings | `server.updateServer`, `server.updateServerWithProgress`, `server.commitDesktopUpdate`, `server.uninstallAcpRegistryManagedBinary`, `server.upsertKeybinding`, `server.removeKeybinding` | ❌ | no self-update; `serverVersion` is the pinned T3 release, and T3 offers a manual update when the app is newer |
| Imported sessions | `agentSessions.import`, `agentSessions.*` (rest) | ❌ | nothing is importable on this host: the agent's conversations live in pi-durable, not a Codex/Claude home dir |
| Session scan | `agentSessions.scan` | ✅ | an empty scan: nothing on this host is importable |
| Secrets | `secrets.answerRequest` | ❌ | tools inherit the host's environment |
